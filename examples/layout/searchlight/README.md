# Searchlight sample

The scene camera and parallax depth, as one small story: a dark kitchen
at night, a searchlight sweeping the room, and — at the end of the
search — a mouse caught eating the cheese.

1. **The search**: the beam wanders from the framed picture to the wall
   clock, the window and the moon, the bookshelf (with its spider), the
   potted plant in the foreground, and the crumb trail on the floor.
   Each stop is a **phase** with its own camera (`look-picture`,
   `look-clock`, …); the game only eases the camera from one phase's
   camera to the next.
2. **Found** (`found` phase): the camera lands on the mouse at the table
   and zooms in; a `!` pops over it (`start: 0.5`), and the pop's
   `complete` event plays the mouse's `startled-seg` through a binding —
   it jumps, its eye goes wide, and it keeps flinching. "FOUND YOU!"
   drops in below.

Enter, Space, or a click skips to the next stop; Esc restarts.

## How the searchlight works

There is no light. The `searchlight` node is a mask clip — black with a
soft-edged hole in the middle, breathing slightly, dust motes drifting
through — placed at **depth 0**, so it is pinned to the screen while the
camera moves underneath. Everything else has a depth, and the camera
moves each node by it:

| node | depth | effect |
|---|---|---|
| `wall` (wall, floor, picture, clock, window) | 0.5 | shifts half as far, zooms 1.41x at zoom 2 |
| `shelf` | 0.7 | between |
| `table`, `mouse`, `alert` | 1 | tracks the camera exactly |
| `plant` | 1.4 | foreground: overshoots, zooms 2.64x |
| `searchlight`, `caption`, `found-text` | 0 | screen-fixed |

The phases' cameras are computed with `lookAt(px, py, depth, zoom,
tilt)` in `gen/main.go`: to center a point of a depth-*d* node the camera
moves `(p - center) / d`, the parallax worked backwards. Open the scene
in the layout tool to see each phase's camera as a framing outline over
the whole room, and press Preview to watch it applied.

Run it, or open it in the layout editor:

```
go run ./examples/layout/searchlight
go run ./cmd/lottie-layout examples/layout/searchlight/assets/searchlight.scene.json
```

The scene, its bundles, and the font are embedded (`go:embed assets/*`),
so the first command works from any directory. `-scene path` runs a
scene file from disk instead — the one the layout tool saved, say — with
its bundles and assets resolved beside it.

Every asset is generated by `go run ./examples/layout/searchlight/gen`
— authored in this repository, one bundle per actor (`wall.lottie`,
`shelf.lottie`, `table.lottie`, `mouse.lottie`, `plant.lottie`,
`mask.lottie`, `alert.lottie`). The generator also copies the stopwatch
sample's Apache-2.0 display font beside the scene, since embedding
cannot reach outside the package directory.

Setting `SEARCHLIGHT_SCREENSHOT=/path/out.png` (and optionally
`SEARCHLIGHT_SCREENSHOT_TICKS`) renders headlessly, writes that frame,
and exits; `-phase found` starts in a given phase, so any stop of the
search can be checked without waiting for it.
